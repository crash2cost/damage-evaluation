## 🎯 סקירה כללית

### מה עושה המודל?
המודל מזהה **איפה** יש נזק על תמונות של רכבים.
- **קלט**: תמונה של רכב פגוע
- **פלט**: מלבנים/פוליגונים מסביב לאזורי הנזק + רמת ביטחון

### מהו YOLO?
**YOLO** = You Only Look Once
- אלגוריתם לזיהוי אובייקטים בתמונות
- מהיר מאוד - מסתכל על התמונה פעם אחת בלבד
- מזהה מספר נזקים בו-זמנית

## 📁 מבנה הנתונים

### מבנה תיקיות:
```
detection-model/
├── dataset/
│   ├── data.yaml          ← קובץ הגדרות (מי/מה/איפה)
│   ├── train/             ← תיקיית אימון (80% מהתמונות)
│   │   ├── images/        ← תמונות לאימון
│   │   └── labels/        ← קבצי תיוג (איפה הנזק)
│   └── valid/             ← תיקיית בדיקה (20% מהתמונות)
│       ├── images/        ← תמונות לבדיקה
│       └── labels/        ← קבצי תיוג לבדיקה
└── src/
    └── train.py           ← קוד האימון
```

### קובץ data.yaml - מה יש בו?
```yaml
path: /path/to/dataset          # איפה הנתונים
train: train/images              # תיקיית תמונות אימון
val: valid/images                # תיקיית תמונות בדיקה
names:
  - damage                       # שם המחלקה: "נזק"
nc: 1                           # מספר מחלקות: 1 (רק נזק)
```

**הסבר:**
- `path` - הנתיב המלא לתיקיית הנתונים
- `train` - איפה התמונות לאימון (יחסית ל-path)
- `val` - איפה התמונות לבדיקה (validation)
- `names` - רשימת השמות של מה שאנחנו מזהים (במקרה שלנו: "damage")
- `nc` - Number of Classes = כמה דברים שונים אנחנו מזהים (1 = רק נזק)

### קבצי Label - איך זה עובד?

**כל תמונה** (למשל `car1.jpg`) **צריכה קובץ תיוג** (`car1.txt`)

**פורמט של שורה בקובץ תיוג:**
```
0 0.3701171875 0.2109375 0.3291015625 0.212890625 ...
```

**מה זה אומר:**
- `0` = מספר המחלקה (0 = damage, כי זו המחלקה הראשונה)
- המספרים הבאים = קואורדינטות של הפוליגון (איפה הנזק)
- כל זוג מספרים = נקודה אחת (x, y)
- הערכים בין 0 ל-1 (יחסית לגודל התמונה)

**דוגמה:**
```
0 0.5 0.5 0.6 0.5 0.6 0.6 0.5 0.6
```
זה פוליגון מרובע במרכז התמונה:
- נקודה 1: (0.5, 0.5) - שמאל למעלה
- נקודה 2: (0.6, 0.5) - ימין למעלה
- נקודה 3: (0.6, 0.6) - ימין למטה
- נקודה 4: (0.5, 0.6) - שמאל למטה

### פונקציה 1: parse_args - קריאת פרמטרים

```python
def parse_args() -> argparse.Namespace:
    parser = argparse.ArgumentParser()
    parser.add_argument("--model", default="yolov8n.pt")
    parser.add_argument("--epochs", type=int, default=200)
    parser.add_argument("--imgsz", type=int, default=640)
    parser.add_argument("--batch", type=int, default=8)
    parser.add_argument("--patience", type=int, default=50, help="Early stopping patience")
    return parser.parse_args()
```

**הסבר שורה אחר שורה:**

**שורה 1:**
```python
def parse_args() -> argparse.Namespace:
```
- `def` - הגדרת פונקציה חדשה
- `parse_args` - שם הפונקציה (לקרוא פרמטרים)
- `()` - הפונקציה לא מקבלת קלט
- `-> argparse.Namespace` - הפונקציה מחזירה אובייקט עם כל הפרמטרים

**שורה 2:**
```python
parser = argparse.ArgumentParser()
```
- יוצר אובייקט שקורא פרמטרים מהטרמינל
- `parser` = המנתח של הפרמטרים

**שורה 3:**
```python
parser.add_argument("--model", default="yolov8n.pt")
```
- מוסיף פרמטר בשם `--model`
- `default="yolov8n.pt"` - אם לא מציינים, ישתמש ב-YOLOv8-nano
- **YOLOv8n** = הגרסה הקטנה והמהירה של YOLO (טובה למערכי נתונים קטנים)
- שימוש: `python train.py --model yolov8s.pt` (לשנות למודל אחר)

**שורה 4:**
```python
parser.add_argument("--epochs", type=int, default=200)
```
- `--epochs` = כמה פעמים לעבור על כל הנתונים
- `type=int` - חייב להיות מספר שלם
- `default=200` - ברירת מחדל: 200 איפוקים
- **Epoch** = סיבוב אחד על כל תמונות האימון
  - דוגמה: 58 תמונות → עובר על כל 58 התמונות = 1 epoch
  - 200 epochs = עובר 200 פעמים על כל התמונות

**שורה 5:**
```python
parser.add_argument("--imgsz", type=int, default=640)
```
- `--imgsz` = image size (גודל תמונה)
- `default=640` - כל תמונה תשונה לגודל 640×640 פיקסלים
- למה? YOLO עובד טוב עם תמונות מסוג 640×640
- תמונות קטנות יותר = אימון מהיר יותר
- תמונות גדולות יותר = דיוק טוב יותר (אבל איטי)

**שורה 6:**
```python
parser.add_argument("--batch", type=int, default=8)
```
- `--batch` = Batch Size (גודל אצווה)
- `default=8` - 8 תמונות בכל פעם
- **מה זה batch?**
  - במקום לעבד תמונה אחת, עובדים על 8 תמונות ביחד
  - מהיר יותר ויעיל יותר
  - batch גדול = זיכרון רב יותר (RAM/GPU)
  - batch קטן = איטי יותר אבל פחות זיכרון
- דוגמה: 58 תמונות ÷ 8 = ~7 batches בכל epoch

**שורה 7:**
```python
parser.add_argument("--patience", type=int, default=50, help="Early stopping patience")
```
- `--patience` = סבלנות (Early Stopping)
- `default=50` - מחכה 50 איפוקים
- **מה זה עושה?**
  - אם המודל לא משתפר ב-50 איפוקים רצופים → עוצר את האימון
  - למניעת overfitting (למידת יתר)
  - חוסך זמן אם המודל כבר טוב

**שורה 8:**
```python
return parser.parse_args()
```
- `parse_args()` - קורא את הפרמטרים מהטרמינל
- `return` - מחזיר את כל הפרמטרים לשימוש בקוד

## 🎨 Data Augmentation - הגדלת נתונים

**בעיה:** יש לנו רק 58 תמונות - זה מעט מאוד!

**פתרון:** Data Augmentation = יצירת גרסאות שונות של אותן תמונות

### פרמטרי Augmentation:

**פרמטרים של צבע (HSV):**

```python
hsv_h=0.015,  # Hue
hsv_s=0.7,    # Saturation
hsv_v=0.4,    # Value/Brightness
```

**מה זה עושה?**
- **HSV** = Hue (גוון), Saturation (רוויה), Value (בהירות)
- משנה את הצבעים בתמונה קלות
- `hsv_h=0.015` - משנה את הגוון ב-1.5%
- `hsv_s=0.7` - משנה רוויה עד 70%
- `hsv_v=0.4` - משנה בהירות עד 40%

**למה זה עוזר?**
- רכבים באור שונה (יום/לילה)
- צבעי רכב שונים
- תנאי תאורה שונים

---

**סיבוב והטיה:**

```python
degrees=10.0,      # סיבוב
translate=0.2,     # הזזה
scale=0.9,         # שינוי גודל
shear=0.0,         # הטיה (שמרנו 0)
perspective=0.0,   # פרספקטיבה (שמרנו 0)
```

**הסבר:**
1. **`degrees=10.0`**
   - מסובב את התמונה עד 10 מעלות
   - דוגמה: צילום מזווית קצת שונה

2. **`translate=0.2`**
   - מזיז את התמונה 20% ימינה/שמאלה/למעלה/למטה
   - דוגמה: הרכב לא בדיוק במרכז התמונה

3. **`scale=0.9`**
   - משנה גודל: 90% עד 110%
   - דוגמה: מצלמה יותר קרובה או רחוקה

4. **`shear=0.0`**
   - הטיה של התמונה
   - שמרנו 0 כי זה יכול לעוות את הנזק

5. **`perspective=0.0`**
   - שינוי נקודת מבט
   - שמרנו 0 כדי לא לעוות יותר מדי

---

**היפוך תמונה:**

```python
flipud=0.5,   # Flip Up-Down
fliplr=0.5,   # Flip Left-Right
```

**הסבר:**
1. **`flipud=0.5`**
   - היפוך למעלה-למטה ב-50% מהמקרים
   - שימושי פחות לרכבים (רכב הפוך?)
   - אבל יכול לעזור ללמידה

2. **`fliplr=0.5`**
   - היפוך שמאל-ימין ב-50% מהמקרים
   - מאוד שימושי! רכב מצד שמאל = רכב מצד ימין

---

**טכניקות מתקדמות:**

```python
mosaic=1.0,      # פסיפס
mixup=0.5,       # ערבוב
copy_paste=0.3,  # העתק-הדבק
```

**הסבר:**

1. **`mosaic=1.0`** - פסיפס
   - לוקח 4 תמונות שונות
   - מחבר אותן לתמונה אחת (2×2)
   - `1.0` = משתמש בזה 100% מהזמן
   - **יתרון:** המודל רואה מספר נזקים בבת אחת

2. **`mixup=0.5`** - ערבוב
   - מערבב שתי תמונות
   - מכפיל אחת ב-0.5 והשנייה ב-0.5
   - `0.5` = משתמש בזה ב-50% מהמקרים
   - **יתרון:** יוצר תמונות "ביניים" שעוזרות לגנרליזציה

3. **`copy_paste=0.3`** - העתק-הדבק
   - לוקח נזק מתמונה אחת
   - מדביק אותו על תמונה אחרת
   - `0.3` = משתמש בזה ב-30% מהמקרים
   - **יתרון:** יוצר קומבינציות חדשות של נזקים

**למה צריך Augmentation?**
- 58 תמונות → 58 × 10 = 580 גרסאות שונות!
- מונע Overfitting (למידת יתר)
- המודל לומד לזהות נזק בתנאים שונים

## 📊 מה קורה במהלך האימון?

### שלב 1: הכנה
```
Loading model...
Downloading yolov8n.pt...  ← מוריד מודל אם צריך
Loading dataset...
```

### שלב 2: תחילת אימון
```
Epoch 1/200:  ← איפוק 1 מתוך 200
  Batch 1/7   ← עובד על batch 1 מתוך 7
  Batch 2/7
  ...
```

**בכל Epoch:**
1. טוען batch של 8 תמונות
2. מחשב חיזויים
3. משווה לתוויות האמיתיות
4. מחשב שגיאה (loss)
5. מעדכן את המשקלים
6. חוזר ל-1 עד שעובר על כל התמונות

### שלב 3: בדיקה (Validation)
```
Validating...
  Precision: 0.90  ← 90% מהזיהויים נכונים
  Recall: 0.25     ← מזהה 25% מהנזקים
  mAP50: 0.45      ← דיוק כללי
```

**מדדים חשובים:**

1. **Loss (שגיאה)**
   - כמה טועה המודל
   - רוצים שזה ירד עם הזמן
   - קרוב ל-0 = טוב

2. **Precision (דיוק)**
   - מתוך כל מה שזיהיתי כנזק, כמה באמת נזק?
   - 90% = 9 מתוך 10 זיהויים נכונים

3. **Recall (שלמות)**
   - מתוך כל הנזקים שיש, כמה מצאתי?
   - 25% = מזהה רק רבע מהנזקים

4. **mAP50 (Mean Average Precision)**
   - ציון כללי של הדיוק
   - 0.5 = 50% (בינוני)
   - 0.9 = 90% (מצוין)
